A Governed Interaction Substrate for Human-Agent Systems

Preserving meaning from semantic intent to deterministic interaction and governed effect · Technical position paper · 2026
Thesis. Humans and agents should participate through one governed interaction substrate rather than parallel application models. Agents contribute typed meaning at bounded semantic tiers; deterministic lowering turns that meaning into interaction and executable actions; humans receive predictable projections of the same authoritative state; and a separate control plane determines who may view, propose, delegate, approve, or execute.

1. The Semantic Split

Most agentic systems give humans and agents different application models. Humans receive screens, forms, dashboards, and approval dialogs. Agents receive prompts, APIs, tools, and loosely structured context. Each path develops its own representation of state, available action, progress, and policy. A recommendation described in prose may not correspond to an executable operation; an API call may bypass the interaction contract visible to a human; and generated presentation may imply meaning the runtime cannot enforce.

Adding orchestration does not close this split. Passing text among agents coordinates conversation, but it does not establish shared semantics, legal transitions, or authority. The architectural requirement is a common substrate in which human and agent participation has the same computational meaning while each participant receives an appropriate projection.

One authoritative interaction state; bounded semantic contribution; deterministic lowering; contextual projection; explicit authority; attributable effects.

2. From Generated Responses to Semantic Composition

Generative interfaces can be organized by what the agent is allowed to produce and where the host regains control. The progression is not simply from text to richer UI. It is a progression from implicit interpretation, through concrete component generation and rigid templates, toward an explicit semantic contract that separates response meaning from runtime presentation.

The fourth model is not another component protocol. The host supplies a closed semantic catalog, preferred response elements, schemas, and validation operations. The agent iterates over semantic artifacts until they satisfy that contract. Only then does the host lower the result according to audience, task, surface, attention, and device context. The same semantic response may therefore become a narrative, timeline, collection, graph, canvas, or headless agent projection without asking the agent to encode those renderings.

Controlled presentation without a fixed response template. The host controls how every semantic element materializes, but the agent remains free to compose any valid semantic structure needed by the response.

3. The Shared Interaction Substrate

The substrate is a medium-blind transition system. It does not privilege a screen, conversation, agent protocol, or device. It evaluates typed events against authoritative state and produces a new state plus effect requests:

Transition rule. (state, event) → (state', effects)

State carries the facts and artifacts declared by the domain contract, together with interaction progress, proposals, approvals, results, and causal relationships. An adaptive specification may choose to preserve evolving hypotheses, failed attempts, branches, or intermediate evidence as first-class artifacts or state. Those concepts are domain semantics, not universal machinery imposed by the substrate. Humans and agents enter events through the same validation boundary. Effects execute outside pure reduction and settle back as validated events, preserving deterministic replay without pretending that networks, models, or tools are deterministic.

A projection is a capability boundary, not a copy of the application. A human projection optimizes comprehension and predictable interaction. An agent projection exposes only the semantic context and operations granted to that participant. A control projection exposes trusted administrative capabilities. Transport carries a selected projection; it does not own policy or create authority.

4. Semantic Tiers and Meaning Preservation

Agents are most useful when they work at the level of domain meaning: investigate this incident, construct the attack path, explain this timeline, or propose remediation. They should not need to choose UI components, mutate application state directly, or generate unrestricted tool calls.

A declarative interaction specification defines a sequence of semantic tiers. Every tier has a controlled vocabulary and a contract. A declared lowering recipe transforms a valid artifact at one tier into a valid artifact at the next:

Tier chain. An → An-1 → … → A1 → T, where T is validated runtime interaction.

An attack path is a semantic artifact; an infinite canvas is one possible presentation. A timeline may become a visual sequence for a human and a structured event list for another agent. Analyze or refresh behavior belongs to the surrounding interaction program, not to a new semantic concept. Factual preservation, omissions, ordering, and semantic coverage belong to validators, not decorative status widgets.

Structure alone is not enough to expose a safe agent experience. The authored contract also declares which target and intent kinds are meaningful, the goals of participation, and the constraints that must survive interpretation. Operation schemas and handlers remain implementation-owned. This keeps agent guidance versioned with domain meaning without turning prose into executable authority.

Adaptive semantic expansion

A fixed specification preserves its authored structure. An adaptive specification may permit policy-allowlisted semantic or executable structure changes and retain the evolving program in checkpoints. This allows an agent to extend the represented problem while it works: adding a hypothesis, relating it to evidence, opening alternative attack-path branches, recording an unsuccessful attempt, or introducing the next investigation choice. The expansion becomes shared semantic structure or state, rather than remaining private reasoning in a transcript.

GraphQuestion answeredArchitectural role
Dependency graphGiven a goal or end state, what prerequisites must be achieved?Works backward from the goal, exposes required subgoals and dependencies, then schedules ready work toward completion.
Consequence graphGiven current state, what has become unlocked or activated?Works forward from achieved facts or changes and identifies newly enabled work that can now be pursued.
Exploratory graphGiven current state and several available paths, which path should be tried next?Uses policy to choose among unlocked paths, records outcomes, and supports backtracking when a pursued path fails.

The graphs are complementary because they traverse the problem differently. A dependency graph starts with the destination and asks what remains necessary. A consequence graph starts with what is true now and asks what can begin because of it. An exploratory graph starts with the currently available frontier but accepts that more than one path may be plausible. Policy ranks or excludes alternatives; execution produces evidence; and failure causes the traversal to walk back, mark the attempted path, and select another eligible branch.

attack-path exploration
To reach a crown-jewel asset, the dependency graph may require initial access, credential acquisition, privilege escalation, and lateral movement. When credentials are discovered, the consequence graph activates the identities, services, and movement opportunities those credentials enable. The exploratory graph chooses an allowed hypothesis, such as an exposed service rather than phishing. If that path is disproven, it records the failed branch, returns to the last viable choice point, and pursues another policy-eligible hypothesis.

These graph decisions still do not grant execution authority. The authored structure policy bounds which hypotheses, relationships, and executable program operations may be added to an adaptive specification. Tool use and external action continue to cross proposal, admission, and effect boundaries. Reactive state machinery may update readiness and computed facts as graph state changes, but that runtime mechanism is distinct from the dependency graph’s semantic role of decomposing a goal into required achievements.

Meaning-preservation invariant. Lowering may specialize structure and presentation, but it must preserve stable semantic identity, responsibility, ports, token contracts, provenance, and declared purpose. Probabilistic generation never bypasses terminal validation.

5. Agent Proposal and Host Application

The terminal interaction program uses a deliberately closed action grammar: assign, derive, emit, invoke, route, and confirm. This is the point at which high-level intent becomes inspectable behavior rather than arbitrary generated code.

Agent participation and authoritative application are separate lifecycles. The agent-facing lifecycle supports understanding and proposal:

Agent lifecycle. manifest → discover → describe → inspect → validate → simulate → preflight → propose

None of these operations applies a change. A proposal crosses a trust boundary into a host-owned lifecycle:

Host lifecycle. receive → authorize → admit → apply, with explicit rejection, failure, status, persistence, and audit paths.
DecisionQuestion answered
AuthorizationMay this actor request this operation?
AdmissionIs this proposal valid for the current target, revision, state, and governing policy?
Application dispositionMay it apply automatically, remain deferred, or require trusted approval?
ApplicationMay the trusted authority perform the resulting transition now?

Local interaction reduces immediately through the deterministic kernel. Agent, model, network, storage, and device work executes through named effect handlers outside that kernel. The host owns credentials, trusted service kinds, endpoint policy, queues, request and response validators, policy evaluation, and execution ceilings. Provider output is untrusted data until it settles through the declared contract. Even when policy permits immediate autonomous application, application remains attributable to the host rather than to model reasoning or tool exposure.

Materialization is deterministic for a specification and immutable external context: M(A, C) = T. It may specialize inner programs while preserving stable identities and topology. This enables adaptive experiences without allowing context or a provider to redefine the application’s semantics at runtime.

6. Multi-Agent Operational Postures

Multi-agent composition benefits from distinguishing how a participant approaches a problem from what it can do and what it is authorized to do. Red, Blue, and Green are useful generalized operational postures:

Red · Challenge and discover

Adopts an adversarial perspective, tests assumptions, explores exposure, and establishes whether a weakness is reachable or exploitable.

Blue · Understand and defend

Observes, classifies, correlates, investigates, explains, detects, and recommends defensive response from available evidence.

Green · Improve and restore

Prioritizes corrective change, proposes hardening and remediation, reduces exposure, and measures restored resilience.

The postures form a governed learning loop: challenge reveals pressure, observation establishes meaning, and improvement changes the system before it is challenged again. They are not security privileges and need not be permanent identities. A participant may adopt one or more postures for a bounded goal.

Red is not merely a Blue workflow with adversarial prompts

In security systems, Red frequently becomes a distinct operating class. Blue work commonly begins with known signals such as alerts, incidents, telemetry, vulnerabilities, or posture findings and follows bounded investigative or defensive tasks. Red work searches for what defenders do not yet know. It is exploratory and research-oriented: observe, hypothesize, attempt, learn, refine, and attempt again. It may run for extended periods, branch across possible attack paths, compose individually minor weaknesses, and produce no confirmed finding.

This distinction belongs primarily to the authored domain and activity model. A Red agent can use an adaptive specification to expand hypotheses and attack-path branches as it explores. The dependency graph keeps the desired end state and unmet prerequisites visible. The consequence graph activates newly possible work as facts are established. The exploratory graph selects, evaluates, and backtracks across alternative hypotheses. Accepted additions and recorded outcomes enter shared semantic structure or state, allowing humans and Blue or Green participants to inspect the same evolving investigation through their own projections.

That autonomy is semantic and policy-bounded. It does not mean every internal thought must be persisted, nor does it move offensive execution into the graph. The authored contract decides which hypotheses, attempts, observations, and branches have shared value. A disproven hypothesis may be a successfully recorded research artifact, while a rejected proposal, failed tool effect, and failed host receipt remain separate lifecycle outcomes.

Red execution also requires a different trust regime: separate identities, planning and execution separation, explicit approval models, isolated environments, tool- and parameter-level policy, network restrictions, rate limits, audit, and blast-radius controls. The Red agent orchestrates bounded offensive tooling; it is not granted an unrestricted offensive toolbox. Blue and Green may use different policies and execution environments even while all three participate through the same semantic and proposal boundaries.

A coordinating agent is posture-neutral. It sequences declared work, passes typed artifacts, and maintains goal context, but it does not become an implicit superuser or inherit the union of all participant capabilities. Coordination is a responsibility; authority remains independently granted.

Semantic handoff, not workflow equivalence. Red-to-Blue transfer commonly takes the form of a narrative, attack-path analysis, evidence package, timeline, or detection-gap assessment. Such artifacts can have typed envelopes, identity, and provenance while retaining the interpretation and human judgment that a rigid procedural API would erase.

7. Data Plane and Control Plane

The shared substrate is the data plane for interaction. It carries domain state, evidence, semantic artifacts, proposals, workflow state, approvals as recorded events, validated action requests, results, and causal history. The control plane establishes who and what may participate.

Agent-to-agent invocation is explicit, bounded delegation. The caller may delegate only a permitted capability, for a declared purpose and scope; the callee receives no ambient access from the caller or orchestrator. Iteration count, campaign duration, or exploratory depth never increases authority. Agent creation is a control-plane and authoring operation. A runtime agent may propose a role, workflow, or policy artifact, but it cannot mint identity, credentials, tools, authority, or policy activation for that proposal. A proposed policy is admitted under already-active policy and cannot authorize itself.

Human control follows from this separation rather than defining the architecture. A person may inspect, amend, reject, approve, pause, redirect, resume, or revoke when policy permits. Each intervention is a typed causal event. The proposal seen by the human is the same semantic proposal evaluated by authorization and delivered to execution.

9. Compact Validation

The architecture is not derived from a single product workflow. Existing scenarios serve as compact tests of its invariants:

Tiered Interaction

A semantic artifact such as a portfolio view or incident timeline lowers independently from its presentation and provider implementation.

Incident Exploration

Verdicts, attack paths, timelines, entities, indicators, and actions preserve source facts while supporting narrative, sequence, and canvas projections.

Governed SOC Work

Evidence, recommendation, human decision, approved request, external action, and settlement remain one attributable causal path.

Operational Postures

Red exploration, Blue investigation and defense, and Green remediation exchange durable semantic artifacts while retaining different activity, execution, persona, and authority models.

Validation criterion. A scenario supports the architecture only if its semantics remain stable when the participant, provider, presentation, transport, or authority grant changes independently.

10. Adoption Boundary

  1. Start with semantic contracts. Name the domain artifacts, evidence, relationships, provenance, and legal outcomes before selecting screens or tools.
  2. Separate tiers from presentation. Let agents contribute typed meaning and let declared lowering choose runtime interaction.
  3. Establish one state and event model. Project it differently for humans, agents, administrators, and headless hosts.
  4. Separate proposal from application. Give agents understanding and proposal operations while trusted hosts own authorization, admission, disposition, application, receipts, and audit.
  5. Make authority independently testable. Model identity, grants, delegation, approval eligibility, policy activation, services, and lifecycle in the control plane.
  6. Move effects to declared edges. Keep credentials and external execution in trusted hosts behind validators and ceilings.
  7. Validate substitutions. Change presentation, provider, participant, or posture independently and prove that semantic and causal invariants still hold.

Conclusion

A trustworthy human-agent system is not a collection of agents connected to a user interface. It is a governed interaction substrate in which meaning survives transformation, state remains authoritative, projection adapts without semantic divergence, and authority is never inferred from generated content or operational posture.

Agents contribute semantic artifacts. Declarative contracts define their vocabulary and lowering. A deterministic runtime owns interaction state. The control plane governs participation and delegation. Trusted hosts execute bounded effects. Humans and agents therefore act through different projections of one process, with a complete causal chain from goal to artifact, presentation, decision, effect, and observed outcome.
