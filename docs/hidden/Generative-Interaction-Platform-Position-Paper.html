A Governed Interaction Substrate for Human-Agent Systems

Preserving meaning from semantic intent to deterministic interaction and governed effect · Technical position paper · 2026
Thesis. Humans and agents should participate through one governed interaction substrate rather than parallel application models. Agents contribute typed meaning at bounded semantic tiers; deterministic lowering turns that meaning into interaction and executable actions; humans receive predictable projections of the same authoritative state; and a separate control plane determines who may view, propose, delegate, approve, or execute.

1. The Semantic Split

Most agentic systems give humans and agents different application models. Humans receive screens, forms, dashboards, and approval dialogs. Agents receive prompts, APIs, tools, and loosely structured context. Each path develops its own representation of state, available action, progress, and policy. A recommendation described in prose may not correspond to an executable operation; an API call may bypass the interaction contract visible to a human; and generated presentation may imply meaning the runtime cannot enforce.

Adding orchestration does not close this split. Passing text among agents coordinates conversation, but it does not establish shared semantics, legal transitions, or authority. The architectural requirement is a common substrate in which human and agent participation has the same computational meaning while each participant receives an appropriate projection.

One authoritative interaction state; bounded semantic contribution; deterministic lowering; contextual projection; explicit authority; attributable effects.

2. The Shared Interaction Substrate

The substrate is a medium-blind transition system. It does not privilege a screen, conversation, agent protocol, or device. It evaluates typed events against authoritative state and produces a new state plus effect requests:

Transition rule. (state, event) → (state', effects)

State carries domain evidence, semantic artifacts, interaction progress, proposals, approvals, results, and causal relationships. Humans and agents enter events through the same validation boundary. Effects execute outside pure reduction and settle back as validated events, preserving deterministic replay without pretending that networks, models, or tools are deterministic.

A projection is a capability boundary, not a copy of the application. A human projection optimizes comprehension and predictable interaction. An agent projection exposes only the semantic context and operations granted to that participant. A control projection exposes trusted administrative capabilities. Transport carries a selected projection; it does not own policy or create authority.

3. Semantic Tiers and Meaning Preservation

Agents are most useful when they work at the level of domain meaning: investigate this incident, construct the attack path, explain this timeline, or propose remediation. They should not need to choose UI components, mutate application state directly, or generate unrestricted tool calls.

A declarative interaction specification defines a sequence of semantic tiers. Every tier has a controlled vocabulary and a contract. A declared lowering recipe transforms a valid artifact at one tier into a valid artifact at the next:

Tier chain. An → An-1 → … → A1 → T, where T is validated runtime interaction.

An attack path is a semantic artifact; an infinite canvas is one possible presentation. A timeline may become a visual sequence for a human and a structured event list for another agent. Analyze or refresh behavior belongs to the surrounding interaction program, not to a new semantic concept. Factual preservation, omissions, ordering, and semantic coverage belong to validators, not decorative status widgets.

Meaning-preservation invariant. Lowering may specialize structure and presentation, but it must preserve stable semantic identity, responsibility, ports, token contracts, provenance, and declared purpose. Probabilistic generation never bypasses terminal validation.

4. Deterministic Runtime and Governed Effects

The terminal interaction program uses a deliberately closed action grammar: assign, derive, emit, invoke, route, and confirm. This is the point at which high-level intent becomes inspectable behavior rather than arbitrary generated code.

Action path. intent → semantic artifact → validation → lowering → authorization → effect → settlement

Local interaction reduces immediately through the deterministic kernel. Agent, model, network, storage, and device work executes through named effect handlers outside that kernel. The host owns credentials, trusted service kinds, endpoint policy, queues, request and response validators, and execution ceilings. Provider output is untrusted data until it settles through the declared contract.

Materialization is deterministic for a specification and immutable external context: M(A, C) = T. It may specialize inner programs while preserving stable identities and topology. This enables adaptive experiences without allowing context or a provider to redefine the application’s semantics at runtime.

5. Multi-Agent Operational Postures

Multi-agent composition benefits from distinguishing how a participant approaches a problem from what it can do and what it is authorized to do. Red, Blue, and Green are useful generalized operational postures:

Red · Challenge and discover

Adopts an adversarial perspective, tests assumptions, explores exposure, and establishes whether a weakness is reachable or exploitable.

Blue · Understand and defend

Observes, classifies, correlates, investigates, explains, detects, and recommends defensive response from available evidence.

Green · Improve and restore

Prioritizes corrective change, proposes hardening and remediation, reduces exposure, and measures restored resilience.

The postures form a governed learning loop: challenge reveals pressure, observation establishes meaning, and improvement changes the system before it is challenged again. They are not security privileges and need not be permanent identities. A participant may adopt one or more postures for a bounded goal.

A coordinating agent is posture-neutral. It sequences declared work, passes typed artifacts, and maintains goal context, but it does not become an implicit superuser or inherit the union of all participant capabilities. Coordination is a responsibility; authority remains independently granted.

6. Data Plane and Control Plane

The shared substrate is the data plane for interaction. It carries domain state, evidence, semantic artifacts, proposals, workflow state, approvals as recorded events, validated action requests, results, and causal history. The control plane establishes who and what may participate.

Agent-to-agent invocation is explicit, bounded delegation. The caller may delegate only a permitted capability, for a declared purpose and scope; the callee receives no ambient access from the caller or orchestrator. Agent creation is a control-plane and authoring operation. A runtime agent may propose a role or workflow, but it cannot mint identity, credentials, tools, or authority for that proposal.

Human control follows from this separation rather than defining the architecture. A person may inspect, amend, reject, approve, pause, redirect, resume, or revoke when policy permits. Each intervention is a typed causal event. The proposal seen by the human is the same semantic proposal evaluated by authorization and delivered to execution.

8. Compact Validation

The architecture is not derived from a single product workflow. Existing scenarios serve as compact tests of its invariants:

Tiered Interaction

A semantic artifact such as a portfolio view or incident timeline lowers independently from its presentation and provider implementation.

Incident Exploration

Verdicts, attack paths, timelines, entities, indicators, and actions preserve source facts while supporting narrative, sequence, and canvas projections.

Governed SOC Work

Evidence, recommendation, human decision, approved request, external action, and settlement remain one attributable causal path.

Operational Postures

Red discovery, Blue investigation and defense, and Green remediation compose around a neutral coordinator while access remains independently controlled.

Validation criterion. A scenario supports the architecture only if its semantics remain stable when the participant, provider, presentation, transport, or authority grant changes independently.

9. Adoption Boundary

  1. Start with semantic contracts. Name the domain artifacts, evidence, relationships, provenance, and legal outcomes before selecting screens or tools.
  2. Separate tiers from presentation. Let agents contribute typed meaning and let declared lowering choose runtime interaction.
  3. Establish one state and event model. Project it differently for humans, agents, administrators, and headless hosts.
  4. Make authority independently testable. Model identity, grants, delegation, approval eligibility, services, and lifecycle in the control plane.
  5. Move effects to declared edges. Keep credentials and external execution in trusted hosts behind validators and ceilings.
  6. Validate substitutions. Change presentation, provider, participant, or posture independently and prove that semantic and causal invariants still hold.

Conclusion

A trustworthy human-agent system is not a collection of agents connected to a user interface. It is a governed interaction substrate in which meaning survives transformation, state remains authoritative, projection adapts without semantic divergence, and authority is never inferred from generated content or operational posture.

Agents contribute semantic artifacts. Declarative contracts define their vocabulary and lowering. A deterministic runtime owns interaction state. The control plane governs participation and delegation. Trusted hosts execute bounded effects. Humans and agents therefore act through different projections of one process, with a complete causal chain from goal to artifact, presentation, decision, effect, and observed outcome.
