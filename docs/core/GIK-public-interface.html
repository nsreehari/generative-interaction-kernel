GIK Public Interface

Kernel & Provider API Reference · Package genui-platform/kernel
The Generative Interaction Kernel (GIK) is a pure interpreter + pure reducer: it holds no domain knowledge, no framework knowledge, and no time beyond a monotonic rev counter. This page is the consumer-facing API — the classes, provider seams, and data types you use to embed the kernel, drive it with events, render its output, and (optionally) run it across a transport. Everything below is re-exported from the package barrel: 
import {
  Kernel, GenUIClient, KernelTransportHost,
  JsonataExpressionProvider, InMemoryStateModel, ManifestRegistry, NullOrchestrator,
} from "genui-platform/kernel";
The language-neutral wire contract (the five GUP messages) lives in 03-protocol; the architectural rationale in 02-architecture.

1 · Quick start

Construct a kernel over a manifest + document, seed it, then feed it events and read the resolved tree. One dispatch is one rev, regardless of how many effects or follow-up events it fans out to.

const kernel = new Kernel(manifest, document, {
  orchestrator: myOrchestrator,   // optional: back invoke/confirm/route/compensate
  sink: consoleSink(),            // optional: receive trace events
});

kernel.init();                              // seed machine states → rev-0 patch
const tree  = await kernel.resolve();       // ResolvedNode tree for a renderer
const patch = await kernel.dispatch({ node: "btn", name: "tap" });   // → { rev, ops }
const state = kernel.state();               // live snapshot (read-only)
The kernel is medium-blind: resolve() returns a framework-neutral ResolvedNode tree, and dispatch() returns ops a renderer applies to its replica. Nothing here knows about React, WinUI, or the DOM.

3 · Time-travel: checkpoint / restore

Because state is pure JSON and the reducer is deterministic, point-in-time capture and restore of state fall out for free — they add no domain knowledge. Reversing an effect's real-world consequence does not, so it stays on the Orchestrator seam. The split:

  • Kernel owns pure-state rollback. State is a Record<string, Json>, so a rollback is just overwriting each namespace — one new rev, replay-safe as a full patch. restore works backward (undo) or forward (redo): it is simply "set state to this value."
  • Host owns the inverse of an effect. The kernel keeps no inverse of a fired charge; the host's Orchestrator.compensate maps it to a real refund, a no-op, or a refusal.

checkpoint() returns a value you hold — { rev, state }, deep-cloned so the next apply() cannot mutate it. The kernel keeps no checkpoint stack or registry. To roll back n checkpoints, hold an array and restore(cpᵢ) jumps directly to any one of them.

The effect journal is a separate, optional query. effectsSince(rev) reports fired effects in causal order (oldest-first), each tagged { rev, seq } — the kernel owns no wall-clock time, so ordering is rev + a monotonic sequence, never a timestamp. A host with its own rollback substrate (a git rev, a DB transaction, an event store) uses checkpoint/restore alone and ignores the journal entirely.

const cp = kernel.checkpoint();                    // hold this value
await kernel.dispatch(chargeEvent);                // state advances; a `charge` effect fires
kernel.restore(cp);                                // pure-state rollback — nothing else touched
const fired = kernel.effectsSince(cp.rev);         // inspect what happened, in causal order
await kernel.compensate(fired.map(e => e.effect).reverse());  // host chooses LIFO reversal → refund
Effects are not idempotent in the world charge → refund → charge is three real transactions, not a return to zero. Only state round-trips to the same value; each effect flip is a new rev and a real-world action, each recorded in the trace. An unhandled or refused compensation is traced, never silently pretended-away. Retention, direction, and redo are host policy — the kernel reports ordered facts and moves state; it never decides what a fired effect means.

4 · Provider seams

These are the pluggable interfaces the kernel depends on. Each has a built-in default, so you implement only the ones you need to customize. Providers extend vocabulary, never the closed shape of the grammar.

Orchestrator — the effect seam

Where a document's invoke/confirm/route actions reach out to do real work (tool calls, HITL approval, routing), and where compensate reverses a prior effect. It owns time and side effects; the kernel and reducer stay pure. Any method may be omitted — unhandled effects are traced and produce no store change. A handler returns an OrchestratorResult (store ops and/or follow-up events) that settles within the same dispatch.

const orchestrator: Orchestrator = {
  async invoke(effect)     { if (effect.tool === "charge") return { ops: [/* receipt */] }; },
  async compensate(effect) { if (effect.tool === "charge") return { ops: [/* refund  */] }; },
};

ExpressionProvider — two positions

The kernel routes value positions (read-exprs, derive) through the full provider, and predicate positions (gates, guards — agent-authored and adversarial) through a safe provider that rejects $eval, lambdas, and transform at compile time (SafeExpressionError). Policy lives in the provider, not the language.

6 · Remote: transport & client

The kernel runs authoritatively on a host; a renderer half runs the pure interpreter over a local replica and never sees the kernel. Both speak the five-message GUP protocol over any TransportProvider.

8 · Wire protocol

When host and renderer are separated, they exchange five envelope-wrapped messages — { gup: "0.1", type, payload }:

MessageDirectionPayload
manifesthost → clientCapability vocabulary (the meta-DSL on the wire).
documenthost → clientThe portable UI-intent tree (DocumentPayload).
patchhost → clientState deltas: { rev, ops }.
eventclient → hostInteraction: { node, name, payload? }.
tracehost → sinkObservability: a TraceEvent.
Delivery is protocol + kernel, not an in-process SDK: the document and deltas are portable, language-neutral artifacts, and every provider is a conformance target. Full message schemas are in 03-protocol.
