GIK Public Interface

Consumer Manual · Public packages: @gik/kernel · @gik/controlface · @gik/agentface · @gik/react · @gik/transport-*
This page is a practical manual for consuming GenUI. It answers one question at each step: which surface do I use, what do I import, and what do I get back? You can consume GenUI at several layers — embed the kernel directly for in-process runtime authority, host a live ControlFace over a bundle, expose that runtime outward through the controlface or agentface tool projections, or connect to it remotely as a render/patch client. The public package surface is: 
import { Kernel, GIKClient, KernelTransportHost, InMemoryStateModel } from "@gik/kernel";
import { ControlFace, createControlFaceDispatcher } from "@gik/controlface";
import { createAgentFaceDispatcher, createStatelessAgentFaceDispatcher } from "@gik/agentface";
import { SseTransportServer } from "@gik/transport-http-sse/server";
import { McpHttpServer } from "@gik/transport-mcp-http";
The language-neutral wire contract (the five GIK messages) is summarised in §12 · Protocol reference at the end of this page, so the manual stays self-contained.
Which surface do I consume? The kernel is the embeddable execution engine. A ControlFace is a host-side live object that wraps one kernel (plus its transport broker) — you construct and hold it inside a host; it is not itself the outward wire surface. The outward callable surfaces are the projections: controlface (the full inspect/drive/time-travel tool catalog) and agentface (an allowlisted subset). A transport (MCP over HTTP, or SSE) carries a chosen projection or the render stream; it never decides capability policy. So agentface is not a second engine — it is controlface filtered.

1 · What you can use

These are the concrete, exported surfaces a consumer touches. Everything below is real code in this repo — pick a row by what you are building.

Kernel@gik/kernelYou own the runtime in-process and want direct resolve/dispatch authority.
ControlFace@gik/controlfaceYou are a host: wrap one bundle in a live object that backs both projections and the render stream.

2 · Pick your surface

  • Own the runtime and call it directly, in one process → embed Kernel (§5).
  • Host one runtime and back both tools and a render stream from it → hold a ControlFace (§6).
  • Give an operator or first-party console full remote authority (inspect, drive, time-travel) → mount the controlface projection over MCP/HTTP (§7).
  • Give an agent a bounded, read-oriented remote surface → mount the agentface projection over MCP/HTTP (§7). Time-travel and emit are intentionally excluded.
  • Ship only authoring/validation tools with no running runtime → createStatelessAgentFaceDispatcher (§7).
  • Render from another process or machine against a patch stream → SseTransportServer + GIKClient (§11).

4 · How the pieces fit

The important boundary is internal vs outward. A ControlFace owns a Kernel and a transport broker as private composition — a transport never binds to that kernel or broker directly. What faces outward is either a tool projection (a JSON request/response catalog) or the render stream (SSE). Capability policy is decided by which projection a host mounts, not by the transport.

Kernel            ← execution engine (resolve / dispatch / state / time-travel)
  └─ ControlFace  ← host-side live object: wraps kernel + broker (private)
       ├─ controlface projection  ← FULL tool catalog        ──► MCP  (e.g. /mcp-control)
       ├─ agentface  projection   ← allowlisted tool catalog  ──► MCP  (e.g. /mcp)
       └─ render stream (attach)  ← patches + tree            ──► SSE  (e.g. /gik)

This mirrors the sample host in samples/control-host/service.ts: it builds one ControlFace, then mounts createAgentFaceDispatcher at /mcp, createControlFaceDispatcher at /mcp-control, and an SseTransportServer at /gik — three outward surfaces over the same live runtime.

5 · Embed the kernel

Quick start

Construct a kernel over a manifest + document, seed it, then feed it events and read the resolved tree. One dispatch is one rev, regardless of how many effects or follow-up events it fans out to.

const kernel = new Kernel(manifest, document, {
  orchestrator: myOrchestrator,   // optional: back invoke/confirm/route/compensate
  sink: consoleSink(),            // optional: receive trace events
});

kernel.init();                              // seed machine states → rev-0 patch
const tree  = await kernel.resolve();       // ResolvedNode tree for a renderer
const patch = await kernel.dispatch({ node: "btn", name: "tap" });   // → { rev, ops }
const state = kernel.state();               // live snapshot (read-only)
The kernel is medium-blind: resolve() returns a framework-neutral ResolvedNode tree, and dispatch() returns ops a renderer applies to its replica. Nothing here knows about React, WinUI, or the DOM.

6 · Host a live ControlFace

A ControlFace is the host-side live object that wraps one bundle. You construct it once and hold it; it is what projections and the render stream bind to. It is not the outward wire surface itself — see §6 for the tool projections and §10 for the render stream.

const controlface = new ControlFace(manifest, document, {
  state,          // optional: pre-seeded StateModel (namespaces already populated)
  orchestrator,   // optional: host effects + compensation (backs invoke/confirm/route/compensate)
  sink,           // optional: TraceSink for resolve/action/effect traces
});
MethodReturnsPurpose
attach(transport, fromRev?)Promise<() => void>Register a render connection (SSE binds here); returns a detach handle. Stream plumbing, not a JSON tool.
emit(event)Promise<Patch>Drive the kernel with one GIKEvent and broadcast the patch to every connected render client.
getState()Record<string, Json>Read the live state snapshot.
getTree()Promise<ResolvedNode>Read the current resolved render tree.
checkpoint()CheckpointCapture an immutable, rev-keyed state snapshot (see §7).
restore(cp)PatchSet state back (or forward) to a checkpoint.
effectsSince(rev)RecordedEffect[]The effects journaled after a rev, in causal order.
compensate(effects)Promise<Patch>Route effects through the orchestrator's compensate seam.
stop()voidDetach every connection (the caller owns any server lifecycle).
Everything behind the face — kernel, reducer, interpreter, broker, GIK codec — is private composition. A transport binds to the face's projection or its render stream, never to the internal kernel or broker.

6 · Expose outward projections

A projection turns a live ControlFace into a callable JSON tool catalog. This is the outward surface you actually mount on a transport. Policy — what a caller may do — lives here, in the choice of projection.

Projection factoryCatalogTypical mount
createControlFaceDispatcher(face)Full: all authoring tools + all runtime tools (getState, getTree, emit, checkpoint, restore, effectsSince, compensate).Operator / first-party control plane.
createAgentFaceDispatcher(face)Allowlisted: authoring tools + getState + getTree only (AGENTFACE_ALLOWLIST). No emit, no time-travel.Agent-facing surface.
createStatelessAgentFaceDispatcher()Authoring tools only — no live runtime attached.Validation/authoring service with no running bundle.

Mount a dispatcher on a transport by handing it the dispatcher's message handler. From the sample host:

const agentMcp   = new McpHttpServer({ path: "/mcp",         handler: createAgentFaceDispatcher(controlface).handleMcpMessage });
const controlMcp = new McpHttpServer({ path: "/mcp-control", handler: createControlFaceDispatcher(controlface).handleMcpMessage });
agentface is controlface filtered agentFaceProjection(face) is literally controlFaceTools(face) filtered by AGENTFACE_ALLOWLIST. There is no second engine and no duplicated tool logic — the agent surface is the full catalog with the unsafe rows removed.

7 · Time-travel & rollback

Because state is pure JSON and the reducer is deterministic, point-in-time capture and restore of state fall out for free — they add no domain knowledge. Reversing an effect's real-world consequence does not, so it stays on the Orchestrator seam. The split:

  • Kernel owns pure-state rollback. State is a Record<string, Json>, so a rollback is just overwriting each namespace — one new rev, replay-safe as a full patch. restore works backward (undo) or forward (redo): it is simply "set state to this value."
  • Host owns the inverse of an effect. The kernel keeps no inverse of a fired charge; the host's Orchestrator.compensate maps it to a real refund, a no-op, or a refusal.

checkpoint() returns a value you hold — { rev, state }, deep-cloned so the next apply() cannot mutate it. The kernel keeps no checkpoint stack or registry. To roll back n checkpoints, hold an array and restore(cpᵢ) jumps directly to any one of them.

The effect journal is a separate, optional query. effectsSince(rev) reports fired effects in causal order (oldest-first), each tagged { rev, seq } — the kernel owns no wall-clock time, so ordering is rev + a monotonic sequence, never a timestamp. A host with its own rollback substrate (a git rev, a DB transaction, an event store) uses checkpoint/restore alone and ignores the journal entirely.

const cp = kernel.checkpoint();                    // hold this value
await kernel.dispatch(chargeEvent);                // state advances; a `charge` effect fires
kernel.restore(cp);                                // pure-state rollback — nothing else touched
const fired = kernel.effectsSince(cp.rev);         // inspect what happened, in causal order
await kernel.compensate(fired.map(e => e.effect).reverse());  // host chooses LIFO reversal → refund
Effects are not idempotent in the world charge → refund → charge is three real transactions, not a return to zero. Only state round-trips to the same value; each effect flip is a new rev and a real-world action, each recorded in the trace. An unhandled or refused compensation is traced, never silently pretended-away. Retention, direction, and redo are host policy — the kernel reports ordered facts and moves state; it never decides what a fired effect means.

8 · Provider seams

These are the pluggable interfaces the kernel depends on. Each has a built-in default, so you implement only the ones you need to customize. Providers extend vocabulary, never the closed shape of the grammar.

InterfaceContractBuilt-in default
ExpressionProvidereval(expr, data, bindings?): Promise<Json>JsonataExpressionProvider({ safe? })
StateModelsnapshot(): Record<string,Json> · get(path): Json · apply(ops: PatchOp[]): voidInMemoryStateModel(namespaces?) · CompositeStateModel(local, contexts)
CapabilityRegistryhas(type): boolean · get(type): CapabilityDescriptor | undefinedManifestRegistry.fromManifest(m)
Orchestratorinvoke? · confirm? · route? · compensate? each (effect) => Promise<OrchestratorResult | void>NullOrchestrator (all effects traced, no-op)
TraceSink(t: TraceEvent) => voidconsoleSink()

Orchestrator — the effect seam

Where a document's invoke/confirm/route actions reach out to do real work (tool calls, HITL approval, routing), and where compensate reverses a prior effect. It owns time and side effects; the kernel and reducer stay pure. Any method may be omitted — unhandled effects are traced and produce no store change. A handler returns an OrchestratorResult (store ops and/or follow-up events) that settles within the same dispatch.

const orchestrator: Orchestrator = {
  async invoke(effect)     { if (effect.tool === "charge") return { ops: [/* receipt */] }; },
  async compensate(effect) { if (effect.tool === "charge") return { ops: [/* refund  */] }; },
};

ExpressionProvider — two positions

The kernel routes value positions (read-exprs, derive) through the full provider, and predicate positions (gates, guards — agent-authored and adversarial) through a safe provider that rejects $eval, lambdas, and transform at compile time (SafeExpressionError). Policy lives in the provider, not the language.

The kernel runs authoritatively on a host; a renderer half runs the pure interpreter over a local replica and never sees the kernel. Both speak the five-message GIK protocol over any TransportProvider.

12 · Protocol reference

When host and renderer are separated, they exchange five envelope-wrapped messages — { gik: "0.1", type, payload }:

MessageDirectionPayload
manifesthost → clientCapability vocabulary (the meta-DSL on the wire).
documenthost → clientThe portable UI-intent tree (DocumentPayload).
patchhost → clientState deltas: { rev, ops }.
eventclient → hostInteraction: { node, name, payload? }.
tracehost → sinkObservability: a TraceEvent.
Delivery is protocol + kernel, not an in-process SDK: the document and deltas are portable, language-neutral artifacts, and every provider is a conformance target. The five message types above are the whole GIK render/patch wire contract; MCP-mounted controlface / agentface tool catalogs are a separate outward surface described in §§5-6.
